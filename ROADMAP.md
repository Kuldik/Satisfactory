# Дорожная карта

Документ для **долгостроя**: фиксирует направление, этапы и необязательные идеи.

---

## Зачем этот проект

Собрать в браузере **узнаваемый factory-builder** (сетка, 3D, строительство, цепочки производства) без претензии на клон 1:1 оригинальной игры. Упор: читаемый код, модульность, ECS как основа симуляции.

---

## Текущая база (что уже есть)

- React + Vite + Three.js, `Engine` с фиксированным тиком и автосейвом (каркас).
- Рендер сцены, камера, ввод, сетка, этажи, загрузка моделей из `kits/`.
- Меню строительства + **паттерны** зданий (JSON-композиции): майнеры Mk1–3, вода, **нефть** (`oil_extractor`), декор.
- Dev-панель: части из китов, линия/точка, экспорт/импорт композиции.
- bitecs: компоненты и черновики систем; **тик движка пока не гоняет симуляцию**.
- Парсер `Docs.json`, типы предметов/рецептов в духе Satisfactory.

---

## Дизайн-документ

Расширенный черновик геймдизайна (логистика, производство, энергия, организация, ХАБ, UI) — **[PROJECT_PLAN.md](./PROJECT_PLAN.md)**. Не финальный; при расхождении с кодом править документ или реализацию осознанно.

## Этапы

Нумерация условная: этапы можно дробить и переставлять. Отмечай выполненное прямо здесь или в `CHANGELOG.md`.

### Этап 1 — Симуляция «скелет»

- [ ] Подключить ECS-мир к `Engine.tick()` (один проход систем в фиксированном порядке).
- [ ] Спавн здания из размещённого паттерна → сущности с `Position`, `Building`, связь с визуалом.
- [ ] Минимальный **производственный** цикл: один рецепт, один станок, вход/выход в «контейнер» без конвейеров.

### Этап 2 — Энергия и зависимости

- [ ] Потребители/генераторы, простая сеть (или упрощённый глобальный баланс на первом шаге).
- [ ] Остановка производства без питания; индикация в UI/HUD.

### Этап 3 — Логистика

- [ ] Конвейеры: порты, соединения, передача предметов по тику.
- [ ] (Опционально позже) трубы и жидкости.

### Этап 4 — Прогрессия и контент

- [ ] Майлстоуны / разблокировки рецептов (данные уже частично описаны типами и парсером).
- [ ] Расширение каталога зданий и паттернов; баланс скоростей/мощностей.

### Этап 5 — Сохранения и полировка

- [ ] Сериализация сущностей и мира в сохранение; загрузка без рассинхрона с сценой.
- [ ] Инвентарь в UI (сейчас заглушка).
- [ ] Звуки (Howler), базовые эффекты по желанию.

### Этап 6 — Масштаб (далёкое будущее)

- [ ] Чанки / отсечение дальности, профилирование при большом числе объектов.
- [ ] UX как у «большой» игры: туториал, настройки, доступность.

## Ледник (идеи без срока)

- Мультиплеер — только если явно понадобится; по умолчанию вне скоупа.
- Импорт сейвов из Satisfactory — нереалистично; не планировать.
- Собственный ассет-пайплайн (glTF, LOD) вместо сырого OBJ — по мере боли от размера и загрузки.

---

## Принципы разработки

1. **Сначала симуляция, потом визуальный шум** — чтобы не упереться в переписывание.
2. **Один источник правды** — состояние игры в ECS/движке, React только отображает и шлёт команды.
3. **Маленькие интеграции** — каждый PR/шаг должен оставлять проект в запускаемом состоянии.
4. **Документы жить вместе с кодом** — крупное решение (формат сейва, протокол сети) — короткая заметка в этом файле или в `game/README.md`.
